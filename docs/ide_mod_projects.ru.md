# Все моды в IDE

Из корня игры запустите `ide\update_mod_projects.bat` (Windows),
`./ide/update_mod_projects.ps1` (PowerShell) или `sh ide/update_mod_projects.sh`
(Linux). Требуются Python 3 и SDK .NET 10; GodotSharp и генераторы 4.6.3
восстанавливаются через NuGet.

Откройте `Cthangover.All.sln`: ядро, проекты тестов и отдельные сборки модов из
`mods/` и `mods_private/`, включая объявленные интеграции и наборы тестов.
Можно открыть один `<id>.csproj` непосредственно из мода. Файлы остаются в моде:
изменение через IDE редактирует настоящий исходник.

Проекты сохраняются в репозиториях модов и коммитятся вместе с ними. Решение
относится к основному репозиторию. Игра продолжает читать manifest и компилировать
код при запуске; `.csproj` не меняет игровой набор модов.

## Обновление

- Новый `.cs` под существующим шаблоном виден автоматически через wildcard.
- После добавления/удаления мода или изменения manifest/depends/DLL выполните скрипт снова.
- Не редактируйте сгенерированные проекты вручную; исправляйте manifest.

Повтор без изменений сохраняет байты и время изменения файлов. Скрипт сообщает
добавленные, изменённые и удалённые проекты. Удаляет только свои помеченные файлы;
ручной проект не перезаписывает. Фикстура в решении не становится частью игры.

## Границы сборок

`sources` и `test_sources` — разные сборки: основной `<id>.csproj` и
`<id>__tests.csproj`. Вложенный набор зависит от хозяина; интеграция — также от
`with`-партнёров. Остальные ссылки берутся из `depends`, включая транзитивные.
Генератор не добавляет зависимости по `using`. Обязательная отсутствующая зависимость
даёт ошибку; необязательная может отсутствовать. Циклы и одинаковые ID отклоняются.
Проверка всей структуры: `dotnet build Cthangover.All.sln`.

Как runtime-сборщик, шаблон `src/*.cs` рекурсивен. Вложенные наборы, скрытые
каталоги и `bin/obj` не попадают в основной код. Моды используют net10.0/C#12,
nullable и implicit using выключены; символы DEBUG/TRACE/TOOLS не добавляются.
Генераторы Godot привязаны к корню игры. Сам `Cthangover.csproj` не меняется.

## Управляемые DLL

Каталог `dll/` сохраняет прежний смысл. Для DLL в другом месте добавьте в manifest:

```json
"references": ["lib/**/*.dll", "vendor/SharedApi.dll"]
```

Это обязательные шаблоны относительно мода: `*`, `?`, `**`. Выход из папки и
отсутствие совпадений запрещены; пересекающиеся шаблоны не дублируют файл.
Вложенные моды сохраняют владение своими файлами. IDE и runtime-компилятор/загрузчик
видят те же библиотеки, включая архивные моды. Изменение байтов DLL меняет ключ
кэша использующего её кода и зависимых модов. Для нативных библиотек остаётся
`depends_native`.

Проекты `source_code/*.csproj` подключаются как исходные проекты библиотек.
Если исходник выпускает ту же сборку, что лежит в `dll/`, IDE выбирает исходный
проект. В релизе без `source_code` используется поставленная DLL. Сгенерированный
`source_code/Directory.Build.props` импортирует общие свойства игры и выносит
сборочные файлы из мода.

Новые результаты сборки находятся в `.ide/obj` и `.ide/bin` корня игры.
Старые `bin/obj` сохраняются и явно исключаются из исходников; `.ide/` игнорируется.
В шаблонах репозиториев модов `info/exclude` также исключает `bin/obj`.

## Отдельный мод без исходников ядра

Корень игры вычисляется относительно проекта. MSBuild-свойство `CthangoverRoot`
переопределяет его. Если `Cthangover.csproj` отсутствует, ссылки берутся из
`CthangoverInstalledDirectory` (по умолчанию тот же корень). Укажите каталог
с `Cthangover.dll` и поставленными рядом управляемыми зависимостями:

```text
dotnet build my_mod.csproj -p:CthangoverRoot=C:/Games/MyGame/ -p:CthangoverInstalledDirectory=C:/Games/MyGame/managed/
```

Для зависимостей-модов предпочтительны их проекты в установленной структуре
`mods/`/`mods_private/`. Запасной путь к уже собранной зависимости:
`.ide/bin/<id>/<Configuration>/net10.0/<id>.dll`. Собственные библиотеки видны через
`dll/` и `references`. SDK нужен для IDE; игроку для runtime-компиляции он не нужен.

Тестовые проекты получают видимость установленного all-mods набора, как ModTestEngine; это не добавляет ссылок в основной код мода. Старые классы на forwarder-базе без partial сохраняют видимое предупреждение GD0001 через ide/godot-runtime.globalconfig: runtime тоже сообщает его как предупреждение. Ошибки C# и недостающие зависимости не подавляются.

Ссылки проектов имеют Private=false: IDE использует API и строит зависимости, но не копирует ядро и reference pack в каждый модовый output. Если authoring config отсутствует в установленной игре, узкая политика GD0001 создаётся в .ide/obj самого проекта. Первый полный build сотен проектов может занимать заметное время; для локальной правки собирайте отдельный проект.
