# Реестр обнаружения — `ModDiscoveryRegistry`

Реестр находит реализации `IModScanner` и `IModLoader` через рефлексию. `Initialize()` проверяет сборки, доступные при инициализации. Метод можно вызывать повторно. Для сборок, загруженных позже, ядро вызывает `RegisterAssembly(assembly)`, а при выгрузке снимает регистрацию через `UnregisterAssembly(assembly)`.

| API | Поведение |
|---|---|
| `Scanners`, `Loaders` | Возвращают потокобезопасные снимки в порядке регистрации |
| `FindScanner(url)`, `FindLoader(url)` | Обходят соответствующий снимок в обратном порядке регистрации. Возвращают первую стратегию, принявшую URL в `IsCanProvide`, или `null` |
| `RegisterAssembly(assembly)` | Находит сканеры и загрузчики в указанной сборке |
| `UnregisterAssembly(assembly)` | Удаляет стратегии указанной сборки |

## Поиск при запуске

`ModBootPipeline.PreparePaths` получает корни от каждого сканера и запоминает, кто предоставил каждый корень. Ядро запускает указанный сканер для его корня и вызывает `FindLoader` для каждой записи. Стратегии, зарегистрированные позже, доступны последующим запросам реестра. Список корней при запуске фиксируется на этапе подготовки путей.

Порядок загрузчиков определяет способ открыть запись. Приоритет источника и версия определяют, какой из обнаруженных кандидатов получит общий ID. Правила выбора описаны в разделе [Ресурсы](/docs/resources/).
