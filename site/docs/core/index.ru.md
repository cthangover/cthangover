# Ядро

Ядро на C# в `Core/` отвечает за запуск, компиляцию в рантайме, поиск ресурсов, инфраструктуру сцен и событий, сохранения, настройки приложения и диагностику. Коллекция определяет состав игры и входную сцену. Игровые сборки регистрируют свои системы через API ядра.

## Сборка и запуск

Для работы из корня репозитория нужны **Godot 4.6.3 .NET** и **.NET SDK 10.0.201** или более новый стабильный набор SDK ветки 10.0. Ядро собирается под `net10.0`. Для экспорта также нужны шаблоны Godot .NET той же версии.

```shell
dotnet build Cthangover.csproj
godot --path .
```

`Cthangover.csproj` компилирует `Core/**/*.cs`. При запуске Roslyn компилирует выбранные игровые сборки и запускает генераторы исходного кода Godot, если они доступны. В релиз входят CLR 10.0.15, эталонные сборки .NET, эталонная сборка ядра с файлом контрольных сумм и генератор Godot. Эталонные сборки позволяют компилировать код в рантайме на компьютере без установленного SDK.

## Запуск и перезагрузка

1. `ModBootPipeline.PreparePaths` определяет источники и пути на потоке Godot.
2. `DiscoverAndCompile` сканирует источники, выбирает кандидатов, разрешает зависимости и подготавливает сборки. При запуске через лаунчер этот этап работает в фоновом потоке.
3. `FinalizeGodotInit` регистрирует сборки, загружает ресурсы и вызывает инициализаторы на потоке Godot. На этапе `Ready` ядро проверяет, требуется ли отслеживание изменений файлов, и устанавливает DebugHost.

Сборки загружаются в выгружаемые контексты. Когда при перезагрузке меняется активный набор, ядро снимает регистрацию затронутых сборок и добавленных ими компонентов, затем освобождает контексты. Ошибки компиляции ищите в категории лога `MODS_COMPILE`, а ошибки обнаружения и манифестов в `MODS_REGISTRY`.

## Кеш компиляции

Ключ `use_assembly_cache` в `config/mod_config.json` включает повторное использование сборок между запусками. Ядро сверяет эталонную сборку с загруженной реализацией и контрольными суммами сборки. Изменение только реализации ядра позволяет переиспользовать совместимые артефакты. Изменение эталонной сборки инвалидирует соответствующие артефакты. Если метаданные отсутствуют или устарели, используется идентификатор версии модуля загруженного ядра. Тогда изменение бинарного файла ядра инвалидирует кеш. На переиспользование также влияют исходники, зависимости и параметры компиляции.
